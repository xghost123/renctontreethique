❌ DATABASE QUERIES (Login, User Search, etc.):
   Error: "could not find driver (Connection: sqlite)"
   
   Cause: Windows system PHP binary doesn't have SQLite compiled.
          The artisan serve command spawns PHP processes that don't 
          respect the custom php.ini configuration with SQLite extensions.
   
   Impact: Login and database-dependent features fail with 500 error.
           Homepage works because it has try-catch fallback for DB.

╔════════════════════════════════════════════════════════════════════════════╗
║                           SOLUTIONS                                        ║
╚════════════════════════════════════════════════════════════════════════════╝

OPTION 1: Use MySQL Instead (Recommended for this situation)
   • Change DB_CONNECTION=mysql in .env
   • Run local MySQL server (no setup needed if using Docker/WSL)
   • Or use a cloud MySQL service

OPTION 2: Switch to Production Server
   • Deploy to Linux/cloud server with SQLite properly configured
   • Use your actual host's PHP with SQLite enabled
   • GitHub Actions or CI/CD can build and test

OPTION 3: Docker
   • Use docker-compose that's already in the project
   • `docker compose up` will handle all PHP/SQLite setup
   • No local PHP configuration issues

OPTION 4: WSL Ubuntu
   • Install PHP + SQLite in Windows Subsystem for Linux
   • Run artisan serve from WSL bash instead of Windows
   • Will have all extensions available
